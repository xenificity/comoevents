# CoMo Events – notes for Claude

Read README.md first. Short version:

- iOS 17+ SwiftUI app, project generated by XcodeGen from `project.yml`. After adding or renaming
  Swift files run `xcodegen generate`. `CoMoEvents.xcodeproj` and `build/` are not committed.
- Build: `xcodebuild -project CoMoEvents.xcodeproj -scheme CoMoEvents -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath build build`
  (do NOT pass CODE_SIGNING_ALLOWED=NO any more: unsigned builds lack the iCloud entitlement and
  CloudKit traps at launch; ad-hoc simulator signing is automatic and needs no account)
- The feed is produced by `feed/aggregate.py` (Python 3, `requests` only). Run it through
  `scripts/update-feed.sh`, which also copies `events.json` into `CoMoEvents/Resources/`.
  Use `--only <source>` while working on one parser. Use `--max-geocode 0` to skip Nominatim.
- Each source is one `src_<name>()` function returning `make_event(...)` records. Add a new
  source by writing another one and appending it to `SOURCES`.
- Coordinates: a source's own coordinates win, except AllEvents / Visit Columbia / Base Local /
  library, where a match in `feed/venues.json` overrides (their coordinates are often campus-center
  guesses). Then Nominatim with a bounded Columbia viewbox. Fix a wrong pin by adding the venue to
  `venues.json`, not by special-casing in code.
- Keep it free: no paid APIs, no server of ours, no analytics. Accounts are Sign in with Apple +
  the user's private CloudKit database (`Support/AccountManager.swift`); the app must keep working
  signed out. Favorites: `EventStore.favorites` is the live copy, mirrored into `UserProfile.favorites`
  via `onFavoritesChanged`; cloud pulls merge back with `mergeFavorites`.
- Entitlements (Sign in with Apple, CloudKit container) are declared in `project.yml`; simulator
  builds with CODE_SIGNING_ALLOWED=NO ignore them, device builds need the App ID capabilities, which
  Xcode's automatic signing adds.
- The app reads `EventStore.remoteURL` (raw GitHub URL of `feed/events.json`) and falls back to the
  bundled snapshot. If the repo moves, change that constant.
- Team ID TU583LSD8W, bundle `com.xenificity.comoevents`. Simulator builds need no signing.
- Nominatim usage policy: max 1 request/second, identify the app in the User-Agent (already done).
  Do not raise the rate.
- Carry-forward: when a source raises or returns zero events, `aggregate.py` keeps that source's
  events from the previous `events.json`. Eventbrite returns nothing from GitHub's runners (bot
  block), so its events only refresh when someone runs `scripts/update-feed.sh` locally and pushes.
- UI: `Support/Theme.swift` holds the brand colors and the `.glass(shape)` modifier (Liquid Glass on
  iOS 26, material fallback below). Use it for any floating control instead of raw materials.
  Deployment target stays iOS 17, so guard iOS 18+/26+ APIs (`Color.mix` is 18+, `glassEffect` 26+).
- Fill images: use `Color.clear.frame(...).overlay { image.resizable().scaledToFill() }.clipped()`;
  a bare scaledToFill image inflates the layout and pushes overlays out of the frame.
- New venue sources go in `POSH_GROUPS` (posh.vip slug), `TRIBE_SITES` (WordPress Events Calendar
  sites), `ICS_SITES` (any public .ics, e.g. an embedded Google Calendar; needs python-dateutil for
  recurring rules) or as a new `src_*`. Venue coordinates for them belong in `feed/venues.json`.
- voxmagazine.com returns 429 quickly: keep the per-host gap in `get()` and never fetch its event pages
  in a loop.
- Install links: never hardcode TestFlight or App Store URLs. Use `AppLinks.install(campaign:)`, which
  points at `docs/get/?c=<campaign>`; that page picks App Store vs TestFlight and passes `ct`. After
  launch, fill `PT` in `docs/get/index.html`. Channels and QR codes: `Marketing/campaign-links.md`.
- CloudKit schema lives in `feed/cloudkit-schema.ckdb`. To ship a schema change: CloudKit Console →
  container → Development → "Import Schema…" with that file (it REPLACES the dev schema) → "Deploy
  Schema Changes…" to Production. The console session expires overnight; Ajay signs in.
- Web app: the site root `docs/index.html` + `app.js`/`app.css`/`cloud.js` (plain HTML/CSS/JS, Leaflet + markercluster from cdnjs with SRI hashes; when
  bumping a library version recompute the hash with `curl -sL URL | openssl dgst -sha512 -binary | base64`).
  It reads `docs/events.json`; keep that copy in the feed workflow and `scripts/update-feed.sh`.
  Time-window and category rules mirror `TimeWindow.swift` and `Event.swift`; change both together.
- Web app iCloud: `docs/cloud.js` is the CloudKit JS layer (same public record types and rules as the
  Swift stores: att-<user>-<event>, friend-<user>, Approval by moderators, 3 reports hide a post). The
  API token lives in `docs/ck-config.js` (`window.CK_TOKEN`), created in CloudKit Console → Production
  → Tokens & Keys, restricted to xenificity.github.io. Empty token = iCloud features hidden.
- Events from flyers go in `feed/extra.json` (title, start, venue are enough; the venue table fills the
  rest). Put the flyer photo in `docs/img/flyers/` and reference its Pages URL as `imageUrl`. Venue
  phone/website/pin for posts come from `feed/venues.json` → `VenueLookup.swift` (app) and
  `Cloud.lookupVenue` (web); add a `website` when adding a venue.
- Event pages for Google: `scripts/build_event_pages.py` turns `docs/events.json` into `docs/e/<slug>/index.html`
  (schema.org Event JSON-LD, one page per event; same-id multi-day repeats become one page with endDate),
  `docs/e/index.html`, `docs/sitemap.xml`, `docs/robots.txt`. It wipes and rebuilds `docs/e` and is deterministic.
  The feed workflow and `scripts/update-feed.sh` run it; slugs are `<title>-<id[:6]>`, so URLs stay stable.
