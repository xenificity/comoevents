# CoMo Events – notes for Claude

Read README.md first. Short version:

- iOS 17+ SwiftUI app, project generated by XcodeGen from `project.yml`. After adding or renaming
  Swift files run `xcodegen generate`. `CoMoEvents.xcodeproj` and `build/` are not committed.
- Build: `xcodebuild -project CoMoEvents.xcodeproj -scheme CoMoEvents -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath build build`
  (do NOT pass CODE_SIGNING_ALLOWED=NO any more: unsigned builds lack the iCloud entitlement and
  CloudKit traps at launch; ad-hoc simulator signing is automatic and needs no account)
- The feed is produced by `feed/aggregate.py` (Python 3, `requests` only). Run it through
  `scripts/update-feed.sh`, which also copies `events.json` into `CoMoEvents/Resources/`.
  Use `--only <source>` while working on one parser. Use `--max-geocode 0` to skip Nominatim.
- Each source is one `src_<name>()` function returning `make_event(...)` records. Add a new
  source by writing another one and appending it to `SOURCES`.
- Coordinates: a source's own coordinates win, except AllEvents / Visit Columbia / Base Local /
  library, where a match in `feed/venues.json` overrides (their coordinates are often campus-center
  guesses). Then Nominatim with a bounded Columbia viewbox. Fix a wrong pin by adding the venue to
  `venues.json`, not by special-casing in code.
- Keep it free: no paid APIs, no server of ours. Analytics are anonymous GoatCounter counts only (see below). Accounts are Sign in with Apple +
  the user's private CloudKit database (`Support/AccountManager.swift`); the app must keep working
  signed out. Favorites: `EventStore.favorites` is the live copy, mirrored into `UserProfile.favorites`
  via `onFavoritesChanged`; cloud pulls merge back with `mergeFavorites`.
- Entitlements (Sign in with Apple, CloudKit container) are declared in `project.yml`; simulator
  builds with CODE_SIGNING_ALLOWED=NO ignore them, device builds need the App ID capabilities, which
  Xcode's automatic signing adds.
- The app reads `EventStore.remoteURL` (raw GitHub URL of `feed/events.json`) and falls back to the
  bundled snapshot. If the repo moves, change that constant.
- Team ID TU583LSD8W, bundle `com.xenificity.comoevents`. Simulator builds need no signing.
- Nominatim usage policy: max 1 request/second, identify the app in the User-Agent (already done).
  Do not raise the rate.
- Carry-forward: when a source raises or returns zero events, `aggregate.py` keeps that source's
  events from the previous `events.json`. Eventbrite returns nothing from GitHub's runners (bot
  block), so its events only refresh when someone runs `scripts/update-feed.sh` locally and pushes.
- UI: `Support/Theme.swift` holds the brand colors and the `.glass(shape)` modifier (Liquid Glass on
  iOS 26, material fallback below). Use it for any floating control instead of raw materials.
  Deployment target stays iOS 17, so guard iOS 18+/26+ APIs (`Color.mix` is 18+, `glassEffect` 26+).
- Fill images: use `Color.clear.frame(...).overlay { image.resizable().scaledToFill() }.clipped()`;
  a bare scaledToFill image inflates the layout and pushes overlays out of the frame.
- New venue sources go in `POSH_GROUPS` (posh.vip slug), `TRIBE_SITES` (WordPress Events Calendar
  sites), `ICS_SITES` (any public .ics, e.g. an embedded Google Calendar; needs python-dateutil for
  recurring rules) or as a new `src_*`. Venue coordinates for them belong in `feed/venues.json`.
- voxmagazine.com returns 429 quickly: keep the per-host gap in `get()` and never fetch its event pages
  in a loop.
- Install links: never hardcode TestFlight or App Store URLs. Use `AppLinks.install(campaign:)`, which
  points at `docs/get/?c=<campaign>`; that page picks App Store vs TestFlight and passes `ct`. After
  launch, fill `PT` in `docs/get/index.html`. Channels and QR codes: `Marketing/campaign-links.md`.
- CloudKit schema lives in `feed/cloudkit-schema.ckdb`. To ship a schema change: CloudKit Console →
  container → Development → "Import Schema…" with that file (it REPLACES the dev schema) → "Deploy
  Schema Changes…" to Production. The console session expires overnight; Ajay signs in.
- Web app: the site root `docs/index.html` + `app.js`/`app.css`/`cloud.js` (plain HTML/CSS/JS, Leaflet + markercluster from cdnjs with SRI hashes; when
  bumping a library version recompute the hash with `curl -sL URL | openssl dgst -sha512 -binary | base64`).
  It reads `docs/events.json`; keep that copy in the feed workflow and `scripts/update-feed.sh`.
  Time-window and category rules mirror `TimeWindow.swift` and `Event.swift`; change both together.
- Web app iCloud: `docs/cloud.js` is the CloudKit JS layer (same public record types and rules as the
  Swift stores: att-<user>-<event>, friend-<user>, Approval by moderators, 3 reports hide a post). The
  API token lives in `docs/ck-config.js` (`window.CK_TOKEN`), created in CloudKit Console → Production
  → Tokens & Keys, restricted to xenificity.github.io. Empty token = iCloud features hidden.
- Events from flyers go in `feed/extra.json` (title, start, venue are enough; the venue table fills the
  rest). Put the flyer photo in `docs/img/flyers/` and reference its Pages URL as `imageUrl`. Venue
  phone/website/pin for posts come from `feed/venues.json` → `VenueLookup.swift` (app) and
  `Cloud.lookupVenue` (web); add a `website` when adding a venue.
- Event pages for Google: `scripts/build_event_pages.py` turns `docs/events.json` into `docs/e/<slug>/index.html`
  (schema.org Event JSON-LD, one page per event; same-id multi-day repeats become one page with endDate),
  `docs/e/index.html`, `docs/sitemap.xml`, `docs/robots.txt`. It wipes and rebuilds `docs/e` and is deterministic.
  The feed workflow and `scripts/update-feed.sh` run it; slugs are `<title>-<id[:6]>`, so URLs stay stable.
- Stats dashboard: `docs/stats/` (public, comoevent.com/stats/). `scripts/build_stats.py` writes
  `docs/stats/data.json` hourly (`.github/workflows/stats.yml`): feed numbers, event/venue history kept in
  `feed/stats/seen.json` (`--backfill` replays git history), and GoatCounter visits/clicks when the
  `GOATCOUNTER_TOKEN` repo secret (read-only API key, site code `comoevent`) is set. Installs, posts and
  attendance are read live from CloudKit in the page. Web counting: `docs/gc.js` (`CE_track(path)`), the
  install page sends an `install/<campaign>` pixel. iOS: `Support/Analytics.swift`, same path names
  (`/ios/open`, `ios-event/<id>`, `click/<name>`), off switch in Profile. Any new tracked action: use the
  same `click/<name>` on web and iOS, and keep the privacy policy in step.
- Arts venues (Oct 2026): `SQUARESPACE_SITES` (?format=json: MOSY /calendar, CEC /events), `src_ragtag` (admin-ajax
  calendar_events POST, every showtime ever: filter by date), `src_stephens` (Localist api/2, type 53310692394891),
  `src_talkinghorse` (TicketLeap inline JSON), `src_mizzouarts` (wp/v2 event + ACF dates), `src_wealwaysswing`
  (season.php image-map titles; season path changes each July), `src_lyceum` (PatronTicket fetchEvents remoting;
  Arrow Rock is outside RADIUS_KM, allowed via `FAR_OK_SOURCES`), `src_caam` (concerts page, one paragraph per
  concert), ICS `maplewoodbarn` + `arcadedistrict` with `ICS_SITE_SKIP`. `dedupe` keeps same-source showtimes at
  different times separate. Venues with no readable listing go in `docs/stats/outreach.json` (shown at /stats/outreach/).
- SEO: `scripts/build_event_pages.py` also writes landing pages (docs/tonight, this-weekend, free, music, family,
  nightlife, arts, food, sports, mizzou, venues/<slug>) with ItemList + BreadcrumbList JSON-LD; the feed workflow commits
  them and runs `scripts/indexnow.py` (Bing/IndexNow; key file docs/<key>.txt — don't delete it). Homepage has WebSite +
  Organization JSON-LD and a static "Browse events" link row in the Upcoming tab (crawlable without JS). Google Search
  Console is verified by a TXT record at GoDaddy.
- SEO round 2 (same builder): holiday pages from `SEASONS` (docs/halloween, thanksgiving, christmas, new-years-eve, valentines,
  st-patricks, fourth-of-july, graduation) exist only inside their date windows, are wiped otherwise, and get linked first in
  every page's Browse row and the homepage's `<!--season-->` markers. Weekend guide: `feed/weekend/<friday>.json` stores each
  weekend's picks (`weekly_post.pick`, frozen from Friday 4 PM) and events (past ones kept), and every stored week is
  re-rendered to docs/weekend-guide/<friday>/ plus the hub docs/weekend-guide/; never delete those JSON files.
  Venue widget: hand-written `docs/embed/venue.html?v=<venue-slug>` (noindex) reads `docs/embed/v/<slug>.json`; files of
  venues with nothing upcoming are kept empty so pasted widgets keep working. Snippet + plain backlink on each venue page.
- Smart search + ranking (Oct 2026): `feed/search.json` is the one concept list (query words, match regexes, venueStrong,
  category/audience/parent links). `aggregate.py enrich()` uses it to add `tags` ("x~" = description only), the
  `religious` category and `score` (0-100 quality) to every event; `update-feed.sh`/feed workflow copy it to
  `docs/search.json` and `CoMoEvents/Resources/search.json`. Clients: `docs/search.js` and
  `Support/SmartSearch.swift` (same logic: concept/typo matching with a real-word guard, narrow words beat broad topics,
  loose fallback, related tail trimmed, repeats collapsed, time words) plus the taste profile (local only: save 3,
  going 4, open 1). Change JS and Swift together. Upcoming ranks within each day; search shows "Best matches".
  Deep link for testing: `comoevents://upcoming?q=hindu%20temple`. To make a search work better, edit search.json, not code.
- Cover pictures (Oct 2026): `scripts/make_covers.py` runs after aggregate (update-feed.sh + feed workflow) and draws an
  art-only cover (no text: apps overlay the title) for every event in the next 60 days without a picture: motif from
  `MOTIFS` (title/venue regex, then tags, then category), colours per category, faint title keyword. Headless Chrome →
  `docs/img/gen/<key>.webp`, `imageUrl` + `imageGenerated: true`; key = title+venue+motif+VERSION (bump VERSION to redraw
  all); unused covers are deleted. Twemoji SVGs cached in `feed/assets/twemoji/` (CC-BY 4.0, credited in Profile/About).
  Never pass `--virtual-time-budget` to Chrome (26 s per image). enrich() doesn't count generated covers in `score`.
- Photos: make_covers.py `fix_photos()` first asks sources for full-size images (`better_url`: Mizzou LiveWhale
  /width/1600/, AllEvents rs:fill:1200:600, Eventbrite original), measures them (cache `feed/cache/imagesize.json`), resizes
  originals > 900 KB to docs/img/gen/p-*.webp, and drops photos under 700x300 (`photoTooSmall`) so a sharp cover is
  drawn instead. Covers are rendered at 2x and saved 1800 px wide.
- Horizon: aggregate.py keeps only events starting within `HORIZON_DAYS` (60).
- Dark mode: web `data-theme` on <html> (inline <head> script; light by default, dark only when `theme`=dark in localStorage), moon/sun
  `.theme-btn` added to every `.page-head` + the map's top-right, OpenFreeMap "dark" style (setStyle diff:false, heat
  re-added on style.load). iOS: `AppearanceButton` (Theme.swift, @AppStorage "appearance") top-right on every tab,
  applied with `.preferredColorScheme` in CoMoEventsApp; light by default even when the iPhone is dark.
- Sounds (synthesised, no files): welcome, favorite, tap, signIn in SoundPlayer.swift and app.js playSound(). iOS ticks via
  `Analytics.tap` (except "save"), tab changes, chips and opening an event; web ticks via one capture-phase click listener.
- Retention: an event stays in the feed until 2 days after it ends (`KEEP_ENDED_DAYS`; no end = start + 3 h, all-day
  = + 24 h); its page and cover go with it. The page cache drops entries older than 14 days; imagesize.json keeps only
  photos of events still in the feed.
- Seasonal stars: `FEATURED` in aggregate.py (Halloween: tag "halloween", 🎃, Oct 1–Nov 2, +25 score) sets `badge`.
  Web and iOS draw badged events as their own emoji pins (`Hotspot.buildWithStars`, `.pin.feat`), clustered only
  with each other. Add a row for Christmas etc.
